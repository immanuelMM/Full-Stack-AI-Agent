Workflow

From idea to shipped, in order

The rules live in CLAUDE.md, so every session follows the same steps. Each new app gets its own folder and its own git repo, next to the agent workspace.

  1. 0

    Two questions first

    Before any planning, the Lead always asks:

    1. What is the name of the app?2. Is this a static website or a full stack web app?
  2. 1

    Plan

    The Planner researches current best practices and writes the plan to <app>/docs/plan/.

  3. 2

    Build

    Backend and Frontend work in parallel. The backend's OpenAPI spec is the contract, and the frontend generates its types from it.

  4. 3

    Test

    QA writes and runs unit, integration and end-to-end tests against what was built.

  5. 4

    Review

    /code-review on every change; /security-review whenever auth, payments, user data or secrets are touched.

  6. 5

    Document

    Docs describes only verified behavior, plus every config variable and the deploy steps.

  7. 6

    Ship

    DevOps adds Docker, CI on every push and pull request, and the hosting setup.

Architecture

How it fits together

The agents are plain configuration files. Agent Studio and the quality gate are Claude Code hooks: small scripts that run on agent events, with no extra npm packages.

Doing the work
Youdescribe a feature or a new app
→
LeadClaude Code, guided by CLAUDE.md
→
Subagents.claude/agents/*.md + standards skills
→
App folders../<app>/, one git repo each
Watching it live
Hook eventsPreToolUse, SubagentStart/Stop, Stop…
→
hook.jssummarises each action and starts the server on the first dispatch
→
server.jsNode server on 127.0.0.1:4747, streams events (SSE)
→
Agent Studioopens in the browser automatically
Keeping it honest
Agent finishesSubagentStop / TaskCompleted hook
→
verify-app.shbuilds and lints every app with changed code
→
Pass → commitFail → errors are sent back and the agent keeps working
🛡️

Guardrails

Agents commit only after builds and tests pass, never push without asking, keep secrets in user-secrets or env vars, and never put secrets in VITE_ variables.

📐

House standards

Two skills define the defaults: dotnet-backend-standards (Clean Architecture, repository + unit of work, JWT) and react-frontend-standards.

🔒

Local and private

Agent Studio listens on localhost only, sends short summaries of actions (not file contents) and stops itself after 3 idle hours.

🧩

Agent teams ready

Any agent can also be started as a teammate in Claude Code's agent teams, sharing a task list and messaging each other directly.

Get started

Run it yourself

You need Claude Code, Node.js 18+, the .NET SDK and Docker (for PostgreSQL).

1 · Start the agents

# the workspace holds the agents and every app
git clone https://github.com/YOUR-GITHUB/full-stack-agent
cd full-stack-agent
claude

2 · Ask for an app

# the Lead asks for the name and type first
> Build me a booking app for a barber shop

# or work on an existing one
> Add loyalty points to cafe-pos-system

3 · Watch Agent Studio

# opens on the first agent dispatch; or by hand:
node .claude/team-viz/server.js --open

# replay the demo
http://localhost:4747/?demo

# turn it off / change the port
TEAM_VIZ=off
TEAM_VIZ_PORT=5050
